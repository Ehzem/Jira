# v3.16 All Work transport negotiation

The destination tenant rejected both prior All Work write transports with HTTP 415:

- v3.14: multipart/form-data
- v3.15: application/x-www-form-urlencoded

Atlassian's current REST prose and Postman collection are inconsistent for
`PUT /rest/api/3/user/columns` and `PUT /rest/api/3/settings/columns`.
The Postman collection currently demonstrates a raw JSON body with
`Content-Type: */*`.

v3.16 therefore negotiates the wire format in this order:

1. raw JSON body with `Content-Type: */*`
2. raw JSON body with `Content-Type: application/json`
3. native multipart/form-data generated by urllib3
4. application/x-www-form-urlencoded
5. the same sequence against the equivalent REST v2 endpoint if v3 rejects all formats

The importer still performs an exact GET read-back of the ordered columns and
reports the transport that Jira accepted. HTTP success alone is not treated as
proof that the visible configuration matches.
